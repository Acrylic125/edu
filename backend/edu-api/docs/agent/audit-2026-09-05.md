# Tutor and chat audit — 2026-09-05

## Implemented

| Finding | Change |
| --- | --- |
| Classification and separate generation routes duplicated policy and added latency | One bounded native tool loop; teaching skills load on demand. |
| Memory expansion ran regardless of need | Explicit learner-scoped search/read tools; reads limited to two exchanges and five images. |
| Transport and UI schemas drifted | Shared Zod contracts, canonical `assistant` role and `messageId`, one message-parts representation. |
| Clients could submit assistant-only parts | Restrict inputs to bounded text and owned attachment references; bound frames and stream indices. |
| Stop/retry could overlap asynchronous runs | Synchronous submission lease retained through cancellation; stale event rejection; persistence failures reported. |
| Topic changes could redirect a running turn | Pin the topic, scope repository updates, bind proposals to their originating topic. |
| WebSocket credentials appeared in URLs | Move credentials to the subprotocol; validate browser origin and incoming-frame session expiry. |
| Client-chosen memory IDs could overwrite existing memory | Conflict handling no longer updates another record. |
| Upload size checks followed full buffering | Bound body reads during streaming and validate small JSON bodies separately. |
| Competing scroll/theme observers synchronized state | LegendList anchoring, external-store subscriptions, and theme context for Mermaid. |
| Mermaid work and caches were unbounded | Serialize rendering; cap source, edges, and cache; retain strict security mode. |
| Cost accounting used incorrect units and guessed prices | Store validated provider cost in micros; explicitly mark unavailable costs. |
| Artificial delays and unnecessary dependencies increased overhead | Remove per-word waits, LangChain/instrumentation, and unused production shadcn CLI; update OpenTelemetry. |

Tutor tools are `load_skill`, `search_memory`, `read_memory`, `verify_answer`,
`set_options`, `create_topic`, and `update_topic`. They preserve explanation,
practice, assessment, diagrams, learning plans, and confirmed plan changes.
Tool schemas and server-side authorization form the trust boundary; prompts
alone do not authorize actions. Verification failures report unavailability
rather than labeling an answer incorrect.

## Remaining work and limits

1. History remains unpaginated and hydrates attachments per message. Add cursor
   pagination and batched hydration before supporting long-lived courses.
2. Topicless turns are not durably persisted because messages/runs belong to a
   topic. A conversation table independent of topics would improve recovery.
3. Learning focus remains global per learner. Pinned runs prevent redirection,
   but independent tab conversations need explicit conversation IDs.
4. Reconnects do not replay missed deltas or reload terminal responses missed
   while disconnected. Add durable replay or history refresh.
5. Session expiry is checked on incoming WebSocket frames; revocation is not
   continuously revalidated. Existing sockets may receive broadcasts until
   closed. Add revocation-aware socket management for stronger guarantees.
6. In-memory throttling, connection limits, and bounded runs do not replace
   durable account spending quotas or distributed abuse controls.
7. Plan mutation, telemetry, response persistence, and Durable Object state are
   not one transaction. A later persistence/telemetry failure can follow a
   successful mutation. Durable operation IDs and reconciliation would improve
   recovery guarantees.
8. The tool loop can exhaust its budget or select unhelpful tools. Run live
   teaching/assessment evaluations before broad deployment, including grading
   accuracy and instruction injection in retrieved material.

## Migration and rollout

This is a coordinated breaking API/UI change. Install dependencies using the
lockfiles in `packages/chat-contract`, `backend/edu-api`, and `web`.
Apply `20260905100000_assistant_role` before starting the backend: it converts
stored `agent` roles to `assistant` and adds `model_usage.cost_source`. Existing
cost rows are marked unavailable because historical accuracy is uncertain.
Deploy client/server together and reconnect existing browser sessions. Abandon
old in-flight proposals; no legacy wire-contract compatibility layer is provided.
No real database was migrated or deployment performed during this audit.
