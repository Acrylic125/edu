# Teaching Math and CS

The course area gives the tutor coverage; the specific learning target determines the explanation. A plan step such as “linear algebra” is too broad for one response. First narrow it to an action the student should be able to perform or justify, such as “interpret an eigenvector” or “compute an eigenvalue for a 2×2 matrix.” Use the student's question as the target when it is more specific than the plan step.

## University topic map

This is a coverage map, not a fixed course sequence. Prerequisites and depth vary by program and learner.

| Math area | Common topics | Best starting form |
| --- | --- | --- |
| Foundations and discrete mathematics | Logic, sets, functions, combinatorics, graphs, induction | Define precisely; compare an example with a boundary case; construct or refute a claim. |
| Calculus and analysis | Limits, derivatives, integrals, multivariable calculus, real analysis | Link a visual or physical meaning to a worked symbolic step; separate intuition from the formal limit or proof. |
| Linear algebra | Vectors, linear maps, bases, eigenvalues, orthogonality | Move between geometry, matrix computation, and the abstract transformation; verify with a small example. |
| Differential equations and dynamical systems | ODEs, PDEs, stability, initial conditions | Start from a model and its assumptions; solve a simple case; interpret the solution and check units or behavior. |
| Probability and statistics | Counting, random variables, distributions, estimation, inference | State the sample space or model and assumptions; compute a small case; interpret uncertainty in context. |
| Algebra and number theory | Groups, rings, fields, divisibility | Give definition, example and non-example; show the key proof move and where each assumption is used. |
| Geometry and topology | Spaces, continuity, shape, invariants | Compare visual and formal representations; test whether a property survives a transformation. |
| Applied and computational mathematics | Optimization, numerical methods, modeling, operations research | Formulate the objective and constraints; trace an iteration; discuss error, convergence, or trade-offs. |

| CS area | Common topics | Best starting form |
| --- | --- | --- |
| Programming foundations | Variables, control flow, functions, types, testing | Ask the learner to predict a short execution trace; inspect the actual state changes and one edge case. |
| Algorithms and data structures | Sorting, search, trees, graphs, complexity | Trace a small input; name the invariant or design idea; analyze time and space after behavior is clear. |
| Theory of computation | Automata, grammars, computability, complexity | Run a string or input through a small machine; distinguish accepted and rejected cases; then generalize or prove. |
| Programming languages | Semantics, type systems, compilers | Trace source through parsing, types, and execution; expose the rule causing the observed result. |
| Computer systems | Architecture, operating systems, concurrency, distributed systems | Follow one request or instruction through components and changing state; identify failure and race cases. |
| Data and networks | Databases, data modeling, queries, networking | Trace a record or packet; show schema/protocol choices, invariants, and failure cases. |
| Software engineering and security | Design, testing, reliability, threats | Use a concrete requirement or threat; compare design choices by behavior and test an edge case. |
| AI, graphics, and interaction | Machine learning, graphics, HCI | Work through a small input-output example; define objective and evaluation, then surface assumptions and limitations. |
| Society and professional practice | Ethics, accessibility, privacy, computing impacts | Analyze a concrete scenario, affected people, competing constraints, and the consequences of a design choice. |

## Response pattern

1. Identify one observable target from the request and current step. If ambiguous, ask one specific question.
2. Introduce only prerequisites needed for that target, defining symbols and assumptions.
3. Choose a representation that exposes the mechanism: worked calculation, proof, trace, example/non-example, or diagram.
4. Explain why the decisive step works and where it fails or does not apply.
5. Offer one small transfer or retrieval check. Use the learner's attempt to decide whether to correct, deepen, or move on. Honor requests for a brief direct answer.

The tutor's normal plan creation still follows a learner-supplied outline exactly. This map guides explanations; it does not silently replace a student's syllabus or advance their step.

## Basis

- The [MAA CUPM guide](https://maa.org/wp-content/uploads/2024/06/2015-CUPM-Curriculum-Guide.pdf) identifies calculus, linear algebra, proofs, data analysis, and upper-level depth as central mathematical experiences. The areas above also include its listed course groups.
- [ACM/IEEE-CS/AAAI CS2023 knowledge areas](https://csed.acm.org/knowledge-areas/) provide the CS coverage; the table groups related areas for tutoring, rather than claiming a single universal degree plan.
- A [meta-analysis of undergraduate STEM teaching](https://doi.org/10.1073/pnas.1319030111) supports active learning over explanation alone. The [Dunlosky et al. review](https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html) supports practice testing and distributed practice. The short check in each lesson is an application of these findings, not a claim that one response can establish mastery.
